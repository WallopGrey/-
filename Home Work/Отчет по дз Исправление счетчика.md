
## 1. Проблема

**Место:** Nginx + Frontend + Backend.

Счётчик увеличивался при каждом обращении к API:

```text
/api/views
```

Поэтому один пользователь при обновлении страницы считался несколько раз.

Исходная логика Backend:

```python
cursor.execute(
    'UPDATE stats SET views_count = views_count + 1 WHERE id = 1'
)
```

То есть каждый GET-запрос увеличивал `views_count` на 1.

---

## 2. Решение

Для подсчёта уникальных посетителей была реализована проверка IP-адреса.

Схема:

```text
Пользователь
    ↓
Nginx
    ↓ X-Real-IP
Flask Backend
    ↓
SQLite
    ↓
Проверка IP
    ├─ IP существует → счётчик не изменяется
    └─ IP новый → IP сохраняется + счётчик увеличивается
```

Nginx уже передавал IP через:

```nginx
proxy_set_header X-Real-IP $remote_addr;
```

В Backend добавлено получение IP:

```python
ip_address = request.headers.get('X-Real-IP')

if not ip_address:
    ip_address = request.remote_addr
```

---

## 3. Изменение базы данных

Добавлена таблица `visitors`:

```sql
CREATE TABLE IF NOT EXISTS visitors (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    ip_address TEXT UNIQUE NOT NULL
)
```

`ip_address` имеет ограничение `UNIQUE`, поэтому один IP не может быть записан несколько раз.

Backend сначала проверяет наличие IP:

```python
cursor.execute(
    'SELECT id FROM visitors WHERE ip_address = ?',
    (ip_address,)
)
```

Если IP отсутствует, он добавляется:

```python
cursor.execute(
    'INSERT INTO visitors (ip_address) VALUES (?)',
    (ip_address,)
)
```

После этого увеличивается счётчик:

```python
cursor.execute(
    'UPDATE stats SET views_count = views_count + 1 WHERE id = 1'
)
```

Если IP уже существует, увеличение не выполняется.

---

## 4. Сохранение базы данных

После исправления логики была обнаружена проблема: `views.db` находилась внутри Docker-контейнера и могла удаляться при его пересоздании.

Для сохранения базы был добавлен Docker Volume.

В `compose.yml`:

```yaml
services:
  backend:
    build:
      context: .
      dockerfile: resume-backend/Dockerfile.backend
    expose:
      - "8000"
    volumes:
      - views-data:/app

volumes:
  views-data:
```

Теперь `views.db` сохраняется в постоянном Docker Volume.

## 6. Проверка счётчика

Первый запрос:

```bash
curl -s http://localhost:8080/api/views
```

Результат:

```json
{"views":1}
```

Повторный запрос с того же IP:

```bash
curl -s http://localhost:8080/api/views
```

Результат:

```json
{"views":1}
```

Счётчик не увеличился, значит повторный запрос с одного IP не считается новым посетителем.

```bash

docker compose up -d
```

После запуска:

```bash
curl -s http://localhost:8080/api/views
```

Результат:

```json
{"views":1}
```

Значение сохранилось, следовательно Docker Volume работает корректно.

## 8. Результат

В результате:

- реализован подсчёт уникальных посетителей по IP;
    
- IP-адреса сохраняются в SQLite;
    
- Nginx передаёт IP в Backend через `X-Real-IP`;
    
- повторный запрос с одного IP не увеличивает счётчик;
    
- база `views.db` сохраняется через Docker Volume;
    
- данные не теряются после пересоздания контейнера;
    
- работа счётчика проверена с помощью `curl`.
